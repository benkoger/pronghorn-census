# Airial: Assisted Labeling & Wildlife Census Platform

Airial is a full-stack platform designed for computer vision-assisted aerial wildlife census and abundance estimation, specifically tailored for aerial surveys such as pronghorn monitoring.

Aerial survey frames can exceed hundreds of megapixels per image, making full-frame manual scanning by human annotators prohibitively slow and resource-intensive. Airial addresses this through a sequential **model-assisted labeling workflow**: candidate detections generated by computer vision models are spatially clustered into standardized crops, which human annotators then inspect, correct, and certify through an interactive verification canvas.

## Core Workflows

```
 [Raw Survey Flights] 
          |
          v
 [Object Detection Model] (Inference)
          |
          v
 [Candidate Predictions]
          |
          v
 [Auto-Cropper] (KMeans Spatial Clustering)
          |   - Clusters detections into 2100x2100 px crops
          |   - Generates draft annotations
          |   - Slices and uploads crops to S3
          v
 [Crop-Verifier] (Human Verification)
          |   - Loads Auto-Cropper output crops in Konva canvas
          |   - Adjusts bounding boxes and corrects class labels
          |   - Deletes false positives and draws missed targets
          |   - Commits certified annotations to PostgreSQL
          v
 [Certified Abundance & Ground-Truth Dataset]
```

1. **Uploader (`/upload/`)**: Coordinates chunked, multipart S3 direct uploads for large raw flight datasets with fault tolerance.
2. **Auto-Cropper (`/auto-cropper/`)**: Groups scattered model detections into standardized bounding crops (default 2100x2100 px) using spatial KMeans clustering (`crop_generator.auto_crop`), producing draft annotations and reviewed areas.
3. **Crop-Verifier (`/crop-verifier/`)**: Human-in-the-loop verification interface. Annotators inspect the output crops produced by the Auto-Cropper on a Vue-Konva canvas, adjusting bounding boxes, correcting labels, removing false positives, and certifying crops.
4. **Data Management & Setup (`/setup`, `/data`)**: System bootstrap, organizational hierarchy, surveys, models, and taxonomies.

## Database Layer Philosophy (Strictly NO ORM)

Airial intentionally avoids traditional ORMs (e.g., SQLAlchemy, Tortoise). Computer vision census operations involve millions of spatial coordinates, bounding boxes, and large image metadata tables where ORM abstractions produce suboptimal query plans, high serialization latency, and N+1 query bottlenecks.

Instead, Airial uses a custom abstraction built on `psycopg3`:
* **Connection Pooling**: Managed via `psycopg_pool.ConnectionPool` with automatic checkout and checkin via the `@connect` decorator.
* **Parameterized SQL**: Queries are constructed safely with `psycopg.sql` to eliminate SQL injection risks while retaining raw database throughput.
* **Typed Object Mapping**: Result rows are deserialized into typed Pydantic models via `class_row`.
* **Dual Identifiers**: All major entities support both internal integer primary keys (`<entity>_id`) for foreign-key join performance and UUIDs (`uuid`) for public API routing.

## Local Development Setup

### 1. Environment Configuration (`.env`)

Create a `.env` file in the root of the repository:

```ini
# Database (PostgreSQL 18)
DB_NAME='testing'
DB_USER='pronghorn_count'
DB_PASS='your_postgres_password'
DB_HOST='prong_gres'
DB_PORT='5432'
DB_SSL='false'

# API & Security
SECRET_KEY='your_random_cryptographic_secret_key'
ORIGIN_URL='http://localhost:5173'
NUM_API_WORKERS=3
SESSION_COOKIE_SAMESITE='Lax'
SESSION_COOKIE_SECURE='false'
SESSION_PERMANENT='true'
SESSION_USE_SIGNER='true'

# Cache & Sessions (Valkey)
VALKEY_HOST='prong_dev_valkey'
VALKEY_PASS='your_valkey_password'
SESSION_REDIS='redis://:your_valkey_password@valkey:6379/0'
CACHE_REDIS='redis://:your_valkey_password@valkey:6379/1'

# Object Storage (S3 / Ceph)
AWS_ENDPOINT_URL_S3='https://s3.arcc.uwyo.edu'
AWS_ACCESS_KEY_ID='your_s3_access_key'
AWS_SECRET_ACCESS_KEY='your_s3_secret_key'
BUCKET_NAME='pronghorn-count-test'

# Frontend Web App
VITE_API_URL='http://localhost:8000/api/v1'

# SpiceDB (ReBAC)
SPICE_URL='prong_spicedb:50051'
SPICEDB_GRPC_PRESHARED_KEY='your_spicedb_preshared_key'
SPICEDB_GRPC_LOGLEVEL='debug'
SPICEDB_DATASTORE_ENGINE='postgres'
SPICEDB_DATASTORE_CONN_URI='postgres://pronghorn_count:your_postgres_password@prong_gres:5432/spicedb_testing?sslmode=disable'
SPICE_TLS='false'

# OAuth 2.0 (Optional)
GOOGLE_CLIENT_ID='your_client_id.apps.googleusercontent.com'
GOOGLE_CLIENT_SECRET='your_client_secret'
```

### 2. Container Execution (Podman or Docker)

Compose configurations are provided for local development and bootstrap:

```bash
# Option A: Local Dev Mode (Restores sample database from local_db/pct_b and SpiceDB backup)
podman compose -f development.compose.yml up -d
# or
docker compose -f development.compose.yml up -d

# Option B: Clean Bootstrap Mode (Initializes fresh schema)
podman compose -f bootstrap-dev.compose.yml up -d
```

Service endpoints:
* **Web Application UI**: `http://localhost:5173`
* **REST API**: `http://localhost:8000`
* **PostgreSQL**: `localhost:5432`
* **Valkey**: `localhost:6379`
* **SpiceDB**: `localhost:50051`

## Running on Host (Outside Containers)

To run the API and Frontend directly on the host machine while keeping supporting services containerized:

### 1. Start Supporting Containers
```bash
podman compose -f development.compose.yml up -d db valkey spicedb spicedb-restore
```

### 2. Run the Backend API
```bash
cd airial_api
uv sync
uv run python app.py
```

### 3. Run the Frontend Web Application
```bash
cd generator_web_app
npm install
npm run dev
```

## Project Status & Development Philosophy

Airial is an active academic research initiative developed by the Ben Koger Lab at the University of Wyoming and Michael B. Lance.

* **Development Reality**: 1 human developer leading architecture and systems design, assisted by coding agents for implementation.
* **Objective**: Rapid delivery of a functional, feature-complete, end-to-end working product.
* **Testing Status**: Automated tests are currently deferred / not implemented by design. Work in this repository prioritizes functional completeness, robust error handling, and working end-to-end capabilities over unit test coverage suites.
